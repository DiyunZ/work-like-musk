# 可选的实时进度 HUD

HUD 辅助 `SKILL.md` 中的教练式工作流程。助手根据项目证据提供建议、决定下一动作，
显示层反映已报告的实际工作。用户明确调用 Skill 开展项目时，在 HUD 启用且可用的
情况下为本任务独立初始化并打开会话；后续轮次沿用。仅提到方法或内部审查不代表
其他任务自动启用。用户不希望启用或 HUD 不可用时，继续提供指导。

此安装默认使用简体中文撰写新的 HUD 说明，用户另有要求时优先遵循。
项目指导使用用户的对话语言；已有标题和记录保留原文。
命令、阶段标识、状态标识及 JSON 字段仍使用固定英文值。
HUD 报告不能替代项目验证或用户要求的交付物。

## 教练节奏与阶段事件

**默认每完成一步，等待用户回应。** 遵循 `SKILL.md` 中的可见指导与完成判定规则。
工作前说明进度条跟踪的范围、当前步骤及完成条件。阶段变化前，先在对话中说明
具体建议和验证结果，再报告 HUD。完成后只更新当前步骤，下一步保持待开始；
在最终回复中说明结论和建议的下一步，等待用户回应后再开展下游工作。
用户在当前步骤内做出的选择，不代表允许完成后续步骤；澄清问题也不会自动推进。

最终回复必须保留范围、当前步骤、教练建议、阶段依据及下一步。过程消息可能折叠，
悬停说明和 CLI 参数不能替代正文记录；每个勾都应能从最终回复中读懂。
明确区分设计层面的结果与实际运行验证。替代方案和结构校验不能证明执行成功。
关键判断尚未验证时保持进行中；必要前提确实阻止工作时标为受阻。超出当前交付范围
的后续步骤保持待办并说明原因；仅仅缺少测量数据，不能以“无需改动”为由完成
加速或自动化步骤。

**只有用户明确要求跨步骤持续执行时，才取消阶段间等待。** 此时可在检查点均有依据
的情况下于同一轮继续工作，但最终回复仍须保留各步结论。用户后来要求恢复等待时，
遵循新的节奏。若用户还希望亲自练习推理或一次回答一个问题，在阶段内部也等待其判断。
默认阶段间等待时显示红色呼吸灯和“等待你的指令”，实际开始下一步才出现旋转环。

询问阶段含义、悬停图标或时间经过不代表推进。普通澄清仍属于当前工作。
新证据推翻旧检查点时，重开对应阶段并清除下游状态；仅提到早期原则不等于重开。
只有必要输入或外部条件确实阻止进行中的工作时才报告 `blocked`；
Question 阶段的正常提问或按用户要求进行的教学等待本身不等于受阻。

跳过未完成步骤时，仍须遵循下文的顺序提醒和随后确认，保留必要交付物。
助手理解用户意图，通过 CLI 报告真实开始与经验证的结果；HUD 不会自行理解对话或
独立担任教练。不要仅因为发送了一条建议就将阶段标为完成。

## 配置和重新打开

根据实际使用的 SKILL.md 确定 skill 目录，使用 Python 3.9 或更新版本运行其中的
`scripts/five_step.py`。以下示例使用默认个人安装路径；安装在其他位置时替换为实际路径。

```sh
python3 "$HOME/.codex/skills/work-like-musk/scripts/five_step.py" setup \
  --project "$PWD" --title "改进当前项目流程"
```

`setup` 创建当前任务会话，或保留并打开已有会话，不会重置进度。
`--no-open` 只初始化或验证状态，不打开界面。任务标识默认仅取自 `CODEX_THREAD_ID`；
不可用时，取得真实任务标识并通过 `--task` 传入，不要猜测、使用共享占位值或借用其他任务。

每轮相关对话开始时及报告进度前，先查看当前任务：

```sh
python3 "$HOME/.codex/skills/work-like-musk/scripts/five_step.py" show --project "$PWD"
```

如果尚无会话且用户已明确调用 Skill 或要求配置 HUD，就运行 `setup`；否则保持未启用。
新会话的五个阶段均为待办，Question 最先就绪。真正开展需求工作，包括提出第一个
相关问题时，才将 Question 标为 `in_progress`。不要复制别的对话进度，也不要因为项目
已有资料而推定阶段完成或补造历史。

会话按规范化项目路径和任务标识隔离。打开会话只登记它，不让后台任务接管前台进度条。
辅助应用将当前窗口的任务标题与本地任务索引核对，解析唯一任务标识，再显示其已登记
会话。切换到未启用的对话、同名或无法识别的标题、不可读会话时，下一次刷新立即隐藏。
不猜测同名任务的归属，不修改任务名称；多个已登记会话重启后仍然保留。
旧项目会话确实已被移除时，其失效路径不会再阻挡同一任务剩余的已登记会话。
如果两个路径的文件都还存在，仍按归属不明处理。

## 报告实际阶段事件

固定阶段顺序为 `question`、`delete`、`simplify`、`accelerate`、`automate`。
普通进度报告使用 `in_progress`、`completed`、`blocked`。
说明使用简明中文，最多 300 字符，不能为空，也不能带首尾空白。

完成说明应包含对应范围内的验收条件和观察到的证据，并与已向用户说明的阶段结论一致。
仅写“草案完成”不足以支持一个实际执行层面的检查点。

```sh
python3 "$HOME/.codex/skills/work-like-musk/scripts/five_step.py" update \
  --project "$PWD" --stage question --status in_progress \
  --expected-revision 1 \
  --reason "正在核对交付要求和项目现有约束"
```

将示例中的 `1` 换成刚刚 `show` 返回的修订号，不能写死。如果修订号已改变，重新读取
并结合用户最新要求核对；不要仅换一个修订号强行提交旧的完成记录。工作开始前报告
进行中，验证后报告完成，回到早期步骤前报告重开，并检查返回的阶段与修订号。
HUD 根据明确报告渲染进度，不会自行解析对话语义。

- 真正开始工作时才开始阶段；证据支持检查点时才完成。完成不会自动开始下一阶段。
- 进入后续阶段前，应完成或获得确认后跳过此前阶段。只有进行中或受阻的阶段才能报告完成。
- 必要输入或外部条件尚未具备时报告 `blocked`，工作恢复时报告 `in_progress`。
- 实际审视后认定无需修改，可以带着审视依据完成该阶段，不必虚构删除、加速或自动化。
- 对较早阶段报告 `in_progress` 或 `blocked` 会重开该阶段，并把后续阶段清回待开始。
- 在已有工作中首次配置 HUD 时，只报告当前证据支持的结果，不要补造历史。
- 仅报告有意义的阶段事件，不要用计时器或估计百分比更新。完全相同的报告保留原时间戳。
- 报告失败不等于项目失败。简要说明问题，保留现有状态并继续独立工作；不要覆盖损坏的状态、
  静默重置，或绕过 CLI 直接写 JSON。

## 跳步与返回早期阶段

例如 Question 已完成、Delete 未完成，用户要求直接开展 Simplify：

1. 保持 Delete 待办。简要说明：先删除不必要的工作，可以避免优化本该移除的部分。
   建议先做 Delete，并询问是否仍要跳过。等待回答期间不开展下游工作。
2. 使用 `request-skip --stage delete --to simplify --reason "实际向用户说明的顺序提醒"
   --expected-revision N`，同时传入通常的 `--project` 和当前 `--task`。
   保存返回的 `skipRequest.requestId`。此命令不会推进任何阶段。
3. 仅在用户随后确认跳过后，使用 `confirm-skip --request-id ID
   --reason "用户在顺序提醒后确认跳过的证据" --expected-revision N`。
   被跳过的步骤会一次性记录为 skipped，Simplify 保持待办。随后真正开展工作时，
   携带最新修订号将 Simplify 标为进行中。
4. 用户接受建议时，正常开始 Delete，旧跳步请求随之失效。如果已经开始 Simplify
   后又决定回到 Delete，重开 Delete；后续阶段清回待办，流向指示随之回退。
   重新检查后续成果后才能再次报告完成。

其他跳过未完成步骤的情况同样处理。早期步骤重开后，不能重复使用旧跳步确认。
直接 `update --status skipped` 会被拒绝。确认记录与修订号保证状态转换的约束，
助手仍须如实理解和报告用户意图，不能虚构用户确认。

## 窗口和持久化

独立的 macOS 辅助应用默认显示为透明且锁定的图标条，位于任务标题三点按钮右侧。
在设置中点击“启用标题跟随”，并为 Five Step HUD 开启 macOS 辅助功能权限。
它仅读取当前任务标题、工具栏位置及本地任务索引中的名称与标识，不读取聊天正文，
也不会操作宿主控件。所有显示位置都必须先核验任务：缺少权限或归属不确定时隐藏进度；
标题旁空间不足时，只有已核验的任务才能回退到菜单栏。切离 Codex 时隐藏进度。

每个阶段保留独立图标：问号对话框、剪刀、收敛线条、闪电、循环箭头。
旋转环表示进行中，只有下一待开始阶段显示红色呼吸灯。
完成显示小勾，受阻显示琥珀色感叹号。“减少动态效果”使用静态标记。
默认背景透明；增加对比度或减少透明度时使用更清楚的实色背景。
悬停可查看任务标题、状态、完整说明和时间；历史文字按记录原文显示。

四条细线中，只有通往下一待办或当前进行中阶段的那一条显示从左向右的粒子。
已走过及尚未到达的连线保持静态。Question 没有前一条连线，新会话因此没有连线粒子。
正常等待指令不会启动阶段。所有阶段结束、出现阻塞或无法读取报告时，粒子停止；
“减少动态效果”保留静态连线。

右侧独立的圆角按钮和进度条右键菜单都可打开设置。“进度显示位置”可选择
任务标题旁、菜单栏或悬浮条。HUD 控件获得焦点时隐藏进度条；设置中保留的名称
标为“上次核验的任务”。返回 Codex 后会重新核验任务，设置中的名称不证明当前宿主任务。
“允许拖动”默认关闭；开启后出现左侧手柄，拖动位置
会随窗口保持。关闭拖动会恢复标题定位。“恢复默认位置”恢复锁定的标题位置，
保留外观和强调色。关闭界面后可重新打开：

```sh
python3 "$HOME/.codex/skills/work-like-musk/scripts/five_step.py" open --project "$PWD"
```

会话位于 `<project>/.work-like-musk/sessions/<sha256(task ID)>.json`，重启后保留。
跳步提醒保存在同目录的 `.skip.json` 文件中，与任务和当时修订号绑定。
不要提交这些任务运行状态，遵守项目已有忽略规则。读取失败时隐藏进度条，避免显示旧进度。
CLI 会拒绝链接到其他位置的运行状态目录，以及非普通文件的状态、跳步请求或锁文件，
并保留原物。应先查明其来源，不要通过直接写状态绕过错误。
只有用户点击“启用标题跟随”才请求辅助功能权限，不安装后台登录项。
系统权限窗口和系统颜色面板的语言由 macOS 决定。
